# zunpy — Roadmap to 0.1.0 (first CRAN release)

Companion to [design.md](design.md). Section references (§) point there.

**Status:** adopted 2026-10-08 from [RFC 0003](https://github.com/pedrobtz/packages/blob/main/rfcs/0003-zunpy-numpy-arrays.md) (its §19). Each stage's **Status:** line says where it stands.

## Sequencing principles

1. **The header parser is proven hostile-safe before anything allocates from it.** Stage 1 is R-free, fuzzed and mutation-checked before Stage 2 builds an R value, because every later stage trusts the plan it hands over (§4, §12).
2. **Read before write.** The readers are tested against NumPy-written fixtures first; the writers are then checked byte for byte against the same fixtures (§8).
3. **Plain arrays before strings, dates, records and archives.** Each later stage adds dtypes or a container, never a new path through the check phase.
4. **Every stage ends with something runnable and tested.**
5. **A stage is done when its exit criteria pass in CI on all three platforms**, not when the code is written.
6. **Gates need canaries.** A fuzz target is trusted once `fuzz_canary` has crashed; a guard once its mutation case has been seen to pass without it.
7. **Change the design in the same commit as the contract.**

Sizes are relative: **S** ≈ a sitting, **M** ≈ a few, **L** ≈ the stage is the week.

**Status never goes in a heading.** A heading is `## Stage N — Title · Size` and nothing else; the state is the **Status:** line under it.

**Tracking.** A `v0.1.0` parent issue and one `stage`-labelled sub-issue per stage, each linking to its heading here. None exists on 2026-10-08; Stage 0 opens them and `.github/scripts/stage-cards.sh` in `pedrobtz/packages` puts the parent on the board. Each stage gains a **What actually happened** block when it closes.

## The release order, and what it costs

zunpy's C includes headers from `zubin` and `zufast` (`LinkingTo`), and its R code calls `zukomp` (`Imports`). On 2026-10-08 none of the three is on CRAN: zufast and zukomp are tagged 0.1.0, and zubin is at `0.0.0.9000` with its release prepared and waiting for zufast (*verified 2026-10-08*). So **zufast, zubin and zukomp must all be on CRAN before zunpy can be submitted** (alignment R10.2). Until they are, `DESCRIPTION` carries `Remotes: pedrobtz/zubin@main, pedrobtz/zufast@main, pedrobtz/zukomp@main`, and Stage 9 removes the field and rebuilds against the CRAN tarballs (R10.3). Every stage before 9 can proceed.

zukomp is needed only from Stage 6 (`.npz`). Declared but unused it is a NOTE, so `Imports: zukomp` and its `Remotes:` entry land with Stage 6, not Stage 0.

## Working rhythm

One pull request per stage: branch `stage-N-<slug>` from `main`; `devtools::document()`, `devtools::test()`, `devtools::test(shuffle = TRUE)` and `devtools::check(cran = TRUE)` clean at 0/0/0 locally before pushing; the PR body states the stage and its exit criteria as a checklist, carries `Closes #<n>` for the stage issue and the `full-ci` label; every CI leg green before merging; then update `.claude/CLAUDE.md`'s current-state paragraph and the **Status:** line.

Local traps the siblings hit: roxygen2 must be 8.1.0 or newer or `document()` rewrites `man/`; `devtools::check()` offline NOTEs on the system clock, silenced with `_R_CHECK_SYSTEM_CLOCK_=0`; `$(C_VISIBILITY)` hides `R_init_zunpy` too unless it is marked `attribute_visible`, and then R silently skips registration.

## Testing strategy, fixed once

- Self-sufficient tests: inputs built inside each `test_that()`, byte-explicit where bytes matter, `withr::local_seed()` for anything random, every file written under a `withr::local_tempdir()`.
- Assert on condition classes and fields (`offset`, `index`, `dtype`, `member`, `limit`), never message text.
- Serial testthat, no `Config/testthat/parallel`; `devtools::test(shuffle = TRUE)` in every definition of done; shared code only in `helper-*.R`.
- Helpers: `helper-bytes.R` (`bytes()` from hex; `npy_header_bytes()` building a prefix by hand for hostile cases), `helper-fixtures.R` (`fixture_path()`, `fixtures_manifest()` reading `MANIFEST.tsv`), `helper-expect.R` (`expect_zunpy_error(expr, class, ...)` checking class and fields; `expect_round_trip(x)`), `helper-skip.R` (`skip_heavy()` on `ZUNPY_SKIP_HEAVY`, set by the gctorture and valgrind legs; `skip_if_no_numpy()` for the conformance tests).
- Fixtures: `tests/testthat/fixtures/npy/`, written by `tools/make-fixtures.py` with NumPy pinned in its header, one `MANIFEST.tsv` row each (dtype, shape, order, NumPy version, SHA-256); read with `colClasses = "character"`; never regenerated by a test (§15).
- CRAN budget: under 15 s; the 2 GiB and 10^6-member cases behind `skip_heavy()`, run in the nightly job.

## Stage 1 — The header parser, R-free · M

**Status:** not started.

**Goal:** a byte string is either a verified plan (dtype, itemsize, shape, order, data offset) or a status with an offset, and nothing hostile gets through.

**Do**

- `src/znp_check.h` (the R-free interface and the plan struct), `src/znp_header.c`: the prefix of §9.1 (magic, version, length field, 16- and 64-byte alignment, D8); the dict grammar of §9.2 as a recursive descent with a depth cap of 8 (D12); the `descr` grammar of §9.3, including the structured list and dict forms (parsed now, built at Stage 5); the shape through `zuf_parse_i64`; Latin-1 or UTF-8 decoding by version.
- The size check: `product(shape) * itemsize` saturating in `uint64_t`, compared with the bytes present; `max_header`, `max_dims`, `max_fields` (§12).
- Every guard on an `if` line carrying `/* GUARD: name */`, with a `test_that("GUARD name")` each.
- A `.Call` entry point `zunpy_header_check(raw, limits)` returning the plan as a list, for tests and for `npy_header()` later.
- `fuzz/fuzz_header.c` under `-DZNP_STANDALONE`, seeded from hand-written headers and, once Stage 2 commits them, from every fixture; `fuzz/fuzz_canary.c`; `tools/run-fuzz` requiring the canary to crash first; `tools/run-lint`; `tools/run-mutation-check` (from zucbor); `hardening.yaml`.
- `test-hostile.R`: every hostile header of §15 as a permanent regression, each asserting its condition class and `offset`.

**Exit**

- The grammars of §9.2 and §9.3 accept every header NumPy's writer emits for the dtypes of §6.1 and refuse the rest.
- Every hostile header of §15 is refused with the right class; every proper prefix of a valid header is `zunpy_parse_error`.
- The canary has crashed; the fuzzer runs its PR budget clean under ASan and UBSan; the mutation check is green.
- `znp_header.c` compiles standalone, without `R.h`.

**Not this stage:** allocating any R value from a plan.

## Stage 2 — Reading plain arrays · M

**Status:** not started.

**Goal:** every numeric, boolean and complex row of §6.1 reads from a NumPy-written file, in both byte orders and both memory orders, with nothing allocated before the check phase passes.

**Do**

- `tools/make-fixtures.py` (NumPy pinned in its header) and `tests/testthat/fixtures/npy/` with `MANIFEST.tsv`; `tools/check-fixtures`.
- `src/znp_build.c`: allocate from the plan only (§12); convert through zubin's `zb_rd_*` kernels, `f2` included; `c8` and `c16` as pairs of `f32` or `f64` (§3); attach `dim`; the one-pass C-order permutation in C (D13).
- `R/decode.R`: `npy_decode()` with `order`, `int64`, `na`, `max_size`, `max_header`, `max_dims`; `npy_header()` over a raw vector (a path arrives at Stage 7).
- The `i4` `NA`, the 2^53 and 2^63 limits, `=` byte order (§18 Q1), zero-length dimensions and the `2^31 - 1` dimension rule (§6.2).
- `native-checks.yaml`, including the `-DZNP_FORCE_BE_HOST` build; `conformance.yaml` with `np.load()` against `npy_decode()` through `reticulate`.

**Exit**

- Every numeric, boolean and complex dtype row of §6.1 reads from fixtures in `<` and `>`, C and Fortran order, and agrees with `np.load()` in the conformance job.
- The `(2**40, 2**40)` header and the `max_size` fixtures show no allocation before the check (§20 criterion 2).
- Sanitizers, valgrind, rchk and gctorture clean; the forced-big-endian build passes.

**Not this stage:** strings, dates, structured dtypes, `.npz`, files and connections.

## Stage 3 — Writing plain arrays · M

**Status:** not started.

**Goal:** R vectors, matrices and arrays become `.npy` bytes that are deterministic and identical to NumPy's.

**Do**

- `src/znp_write.c`: the header formatted into a fixed stack buffer exactly as §8 describes (key order, quoting, trailing comma, one-element tuple, 64-byte padding, version choice); data through a zubin builder owned by a finalized external pointer (§4, §13); little-endian always.
- `R/encode.R`: `npy_encode()` with `dtype`, `order`, `na`; `npy_dtype()`; the numeric, logical, complex, raw and `integer64` rows of §7.1; `dtype =` narrowing through zubin's writers, refusing out-of-range values with their index.
- `order = "C"` permuting on write.
- `test-round-trip.R`: the property of §7.4 over generated arrays of every numeric dtype, 0 to 4 dimensions, both orders, with `NA`, `NaN`, `-0` and infinities.
- `conformance.yaml` extended: zunpy's bytes loaded by `np.load()` and compared.

**Exit**

- §7.1's numeric rows and §8 hold; each encode is byte-identical across two calls and to NumPy's own output on the fixture set (§20 criterion 5).
- The round-trip property holds over the generated corpus.

**Not this stage:** strings, dates, data frames, `.npz`, writing to files.

## Stage 4 — Strings, dates and times · S

**Status:** not started.

**Goal:** `S<n>`, `U<n>`, `M8` and `m8` both ways, with every lossy row of §7.4 behaving as documented.

**Do**

- `S<n>`: NUL-stripping, `encoding`, `strings = "raw"`; UTF-8 validation through `zuf_utf8_valid`.
- `U<n>`: UCS-4 in the file's byte order to UTF-8, refusing surrogates and code points above U+10FFFF; the reverse on write, `n` in code points (and §18 Q2 decided).
- `M8` and `m8` per §6.1 and D7: `Date`, `POSIXct` in UTC, `difftime`, `integer64` for other units and under `datetime = "integer64"`; NaT as `NA`; `unit =` on write, refusing a fraction finer than the unit.
- Fixtures for each row; the §7.4 table as a test file, one `test_that()` per row.

**Exit**

- §6.1's string and time rows read from fixtures and agree with NumPy; §7.1's `character`, `factor`, `Date`, `POSIXct` and `difftime` rows write and agree.
- The lossy table of §7.4 is verified row by row.

## Stage 5 — Structured dtypes · M

**Status:** not started.

**Goal:** record arrays become data frames and back, through zubin layouts.

**Do**

- `R/structured.R`: the `descr` list and dict forms (from Stage 1's plan) to a zubin layout spec; explicit offsets as `x<n>` padding; subarray fields as `name:type[n]`.
- The fields zubin has no type for (§3, §6.3): `U<n>` as `b<4n>`, `M8` and `m8` as `i64`, `c8` and `c16` as two float fields, converted after `bin_unpack()` and before `bin_pack()`.
- `npy_shape` for k > 1 dimensions (D11); `max_fields`.
- Data frames on write (§7.3): field names validated, version 3.0 headers when a name is not Latin-1 (§18 Q5).
- zubin conditions re-raised as zunpy classes with the same fields (§11).

**Exit**

- §6.3 and §7.3 hold on NumPy fixtures, packed and `align=True`, with subarray fields; round trips through NumPy in the conformance job.
- No `zubin_error` escapes zunpy.

**Not this stage:** nested structured fields (§2).

## Stage 6 — `.npz` · M

**Status:** not started.

**Goal:** ZIP archives of `.npy` members, read and written, safely and deterministically.

**Do**

- `Imports: zukomp (>= 0.1.0)` and `pedrobtz/zukomp@main` in `Remotes:`.
- `R/npz.R` and `src/znp_zip.c`: the three records of §10 through `bin_layout()`; the central-directory walk; ZIP64 extra fields; member lookup by name; `max_members`; `max_size` over the declared uncompressed sizes before any inflation.
- Method 8 through `komp_decompress(codec = "deflate-raw", max_output = usize)` and `komp_compress(codec = "deflate-raw", level = 6L)` (D5); CRC-32 in zunpy's C (D6).
- Writing per §8: list order, `<name>.npy`, fixed timestamps, no extra fields; §18 Q3 (member names) decided.
- `npy_decode()` and `npy_encode()` dispatch on the magic (`\x93NUMPY` against `PK\x03\x04`, D2); `names =`; `member` on conditions.
- Hostile archives of §15: 2^32 declared members, a 2 GiB `usize` over a 100-byte stream, a CRC mismatch.

**Exit**

- Stored and deflated `.npz` from `numpy.savez` and `numpy.savez_compressed` read; ZIP64 fixtures read; `names =` touches only the named member.
- Two writes of the same list are byte-identical, and NumPy loads them.
- Every hostile archive is refused with its class.

**Status:** not started.

**Exit**

## Explicitly not in 0.1.0

Nested structured fields · lazy and memory-mapped reads · `npz_*` aliases · object dtype and pickles · `float128` · appending to a `.npz` · a C API (§2).

## Risk register

| Risk | Stage | Mitigation |
|---|---|---|
| a header crafted to exhaust the parser | 1 | the depth cap, `max_header`, the fuzzer with its canary, the mutation check |
| a provider's CRAN release slips | 9 | every other stage proceeds; zunpy waits last in the order of §14 |
| zubin's API changes before its 0.1.0 | 2–5 | `Remotes:` pins `main`; zunpy is the first consumer, so it reports breaks as zubin issues |
| NumPy changes its header layout or padding | 3, 8 | fixtures record the NumPy version; the conformance job regenerates and diffs them |
| `U<n>` columns too wide to write sensibly | 4 | §18 Q2's `nchar =` override |
| the audience is smaller than the design assumes | all | §21: the package is still the worked example of a zubin consumer |

## After 0.1.0

1. Lazy and memory-mapped reads in zunpy 0.2.0, when zubin 0.3.0 (views) and 0.4.0 (memory maps) ship.
2. Nested structured fields, if a user brings a file.
3. `npz_*` aliases, if asked (D2).
