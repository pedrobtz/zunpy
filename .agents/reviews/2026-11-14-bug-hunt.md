# zunpy bug hunt, 2026-11-14

Commit [`0e74ace`](https://github.com/pedrobtz/zunpy/tree/0e74aced589ab752ee03669e83d565096103abb4), the head of #40: the release-review fixes, not yet merged. `main` would only have rediscovered #25.

**Hunters:** three, on Fable, one at a time, each blind to the others' reports. **Slices:** the R layer, decoding (`.npy` and `.npz` read), and emitting (`.npy` and `.npz` write). **Coordinator:** the session's own model, which built the map, re-ran every trigger on the same pinned install and graded the findings. **Counterparts:** NumPy 2.3.3, Python `zipfile`, `ast.literal_eval`, the `zip` and `unzip` CLIs, and a loopback HTTP server.

**Built here:** macOS x86_64, R 4.6.2, Apple clang; zubin 0.1.0, zufast 0.1.0 and zukomp 0.1.0 from CRAN. The R-free check phase was also built standalone under ASan and UBSan.

**Unverified:** a real big-endian host (CI has only the `-DZNP_FORCE_BE_HOST` build); Windows; the R package itself under ASan; members and arrays over 2^31 elements or 4 GiB; `https://` and `ftp://` URLs; non-UTF-8 multibyte locales (only C and `en_US.UTF-8` were run).

Probes are in [`2026-11-14-bug-hunt-probes/`](2026-11-14-bug-hunt-probes/).

## Target map

Boundaries are taken from `.agents/assurance.md` (#57): `.npy` read (plain, `S`/`U`/`V`/`M8`/`m8`, structured, C and F order, the direct path), the header grammar, `.npy` write, `.npz` read and write, and connections. The limits are `max_size`, `max_header`, `max_dims`, `max_fields`, `max_members`, depth 8, subarray dimensions 8, 64 dimensions, 1,024 columns, the 65,535-byte header version switch, the ZIP64 thresholds, 2^31 - 1 and 2^53. Numbers cross into C as dtype widths parsed from strings, shapes, limits and time scales. There are no long-lived objects. The one platform branch is the `memcpy` fast path.

The weakest spots, probed first, were the assurance gaps #46–#56, the code #40 added, and limits tested only on their refusing side.

## 1. Read a compressed `.npy` by one rule on every route — #58, high, reproduced

- **Where:** [`R/read.R` `znp_read_direct()`](https://github.com/pedrobtz/zunpy/blob/0e74ace/R/read.R#L90-L135) and `znp_read_bounded()`; `R/zu_source.R`.
- **Trigger:** a gzip-written `<f8` whose compressed size equals its declared size. `npy_read(path)` returns different numbers with no error; `npy_read(gzfile(path))` is right. In the common case `npy_read(path)` refuses while `npy_header(path)` and `npy_read(file(path))` read the file.
- **Cause:** `file()` then `open("rb")` decompresses, while `file(path, "rb")` and `file.size()` see the compressed bytes.
- **Fix:** refuse compressed input on every route, or read it decompressed on every route, with `max_size` in decompressed bytes.
- **Family:** 1. **Siblings:** the direct path (wrong values), the general path (refuses) and `npy_header()` (reads); bzip2 and xz the same.
- **Test the suite lacked:** a differential over every read route for gzip, bzip2 and xz files.
- Found independently by hunters 1 and 2.

## 2. Check name uniqueness after UTF-8 normalisation — #59, high, reproduced

- **Where:** `R/npz.R` `znp_npz_encode()` and `R/encode.R` `znp_encode_records()`.
- **Trigger:** names `"é"` and the bytes-marked `"\xc3\xa9"`. The `.npz` gets two `é.npy` members, and `np.load()` returns the second member's data for both keys. The record header gets two fields called `é`, which NumPy refuses.
- **Cause:** #40 normalises after the duplicate check.
- **Fix:** check after `znp_utf8_names()`, and in C.
- **Family:** 3. **Siblings:** `.npz` keys and record fields both fail.
- **Test the suite lacked:** one name in three encodings on every route that takes names.

## 3. Refuse an end record that disagrees with the directory — #60, medium, reproduced

- **Where:** `src/znp_zip.c` `znp_zip_check()`.
- **Trigger:** a 3-member archive whose end record says 2. zunpy returns 2 members; NumPy and `zipfile` return 3. A ZIP64 end record behaves the same.
- **Fix:** require the walk to end at the directory's declared end, as a new guard.
- **Family:** 4.
- **Test the suite lacked:** end-record counts above and below the directory's, plain and ZIP64.

## 4. Refuse native strings that `enc2utf8()` would rewrite — #61, medium, reproduced

- **Where:** `R/encode.R` `znp_prepare()` and `znp_utf8_names()`.
- **Trigger:** under `LC_ALL=C`, the unmarked string `caf\xc3\xa9` is written as the text `caf<c3><a9>`. The same happens to values, field names and member names.
- **Family:** 4.
- **Test the suite lacked:** the string tests again under a C `LC_CTYPE`.
- Found independently by hunters 1 and 3.

## 5. Round-trip 0-d record arrays (regression in #40) — #62, medium, reproduced

- **Where:** `R/encode.R` `znp_shape_ok()` and `src/znp_write.c` `read_shape()`, which require at least one dimension.
- **Trigger:** `npy_encode(npy_decode(<records, shape ()>))` fails. It worked before #40.
- **Family:** 3.
- **Test the suite lacked:** re-encode every records fixture, the 0-d one included.

## 6. Keep a big-endian datetime's dtype on write-back — #63, medium, reproduced

- **Where:** `R/encode.R:167`, whose pattern requires `<`.
- **Trigger:** `>M8[h]` decodes to an integer64 that is written back as `<i8`.
- **Family:** 3.

## 7. Round to half once, as NumPy does — #64 and zubin#105, medium, reproduced

- **Where:** `src/znp_write.c:147`, through zubin's `zb_wr_f16le` (`double` to `float` to half).
- **Trigger:** `1 + 2^-11 + 2^-40` is written as `00 3c` where NumPy writes `01 3c`. 3,050 of 40,008 near-midpoint values differ by one ulp, and NaN payloads also differ.
- **Family:** none. Two correct roundings compose into a wrong one. See Cross-cutting.

## 8. Read only the directory in `npy_names()` — #65, medium, reproduced

- **Where:** `R/npz.R:25`.
- **Trigger:** `npy_names(con)` consumes the whole connection, and `npy_names(path, max_size = size - 1)` is refused.
- **Family:** 3, since `npy_header()` reads only the header.

## 9. Bound allocations by elements, not header bytes — #66, medium, reproduced

- **Where:** `src/znp_header.c:1044-1049` and `src/znp_text.c`.
- **Trigger:** a 130-byte header, `<U536870912` with shape `(0,)`, peaks at about 2.15 GB. `|S0` with shape `(2^31,)` fails with a base `simpleError`.
- **Family:** 1, since `max_size` bounds bytes in one check and elements in another.

## 10. Datetime counts at the int64 edge — #67, medium, reproduced (overflow by inspection)

- **Where:** `src/znp_time.c:76`.
- **Trigger:** the largest `M8[ns]` can't be written back, and `whole * scale + frac` can overflow `int64`, which is undefined behaviour. Counts above 2^53 are written in `s`, `D` and `m8` that zunpy's own reader refuses.
- **Family:** 1.

## 11. Decide float overflow to `Inf` — #68, medium, reproduced

- **Trigger:** `1e300` written as `<f4` or `<c8` becomes `Inf` with no signal. #40 documents this only for `<f2`.
- **Family:** 3.

## 12. Make `npy_dtype()` report what `npy_encode()` writes — #69, medium, reproduced

- **Trigger:** `npy_dtype(c("a", "bbb"))` is `"<U"` where `<U3` is written, and data frames and lists are refused.
- Found independently by hunters 1 and 3.

## 13–18. Low

- **#70:** the ZIP64 thresholds differ from `zipfile`'s. At 65,535 members a stored archive isn't byte-identical to `savez()`.
- **#71:** `npy_header()` rounds dimensions above 2^53, and cites a `max_size` it doesn't take.
- **#72:** the writer emits files that its own reader, and NumPy, refuse at the defaults: about 600 or more columns, or 33 to 64 dimensions. Found by hunters 1 and 3.
- **#73:** keys `a` and `a.npy` give an archive whose members NumPy can't tell apart. Found by hunters 1 and 3.
- **#74:** a malformed difftime fails with base errors.
- **#75:** documentation drift: `u4` with `integer64`, the `M8[h]`/`[m]`/`[W]` classes, `na = "allow"` outside the default dtypes, and warnings without a `member` field.

## Cross-cutting

- **#40 fixed instances, not classes.** Three findings sit in code #40 added or touched. Its uniqueness check runs before its own normalisation (#59). Its new shape check forgot the 0-d case (#62). Its `<f2` documentation of `Inf` left out `<f4` and `<c8` (#68). A fix PR needs the same sibling grep as a review.
- **R's own I/O and encoding helpers have two meanings.** `file()` decompresses or not depending on how it is opened (#58), and `enc2utf8()` returns valid UTF-8 that is not the input (#61). Both pass every check zunpy makes after them.
- **Candidate rule for `correctness.md`, family 5, "two correct steps compose into a wrong one":** narrowing in two steps (`double` to `float` to half, #64), or checking before a transformation instead of after it (#59). The test that catches it is a differential with a reference that does the operation in one step.
- **Writer and reader limits are set separately** (#72, #67): the writer produces what the reader refuses. Each limit should be one constant shared by both directions, or the writer should warn.

## Not reached

- Members or arrays over 2^31 elements or 4 GiB (memory).
- A big-endian host.
- `https://` and `ftp://` URLs.
- Non-UTF-8 multibyte locales.
- Interrupts during a write.
- Libfuzzer itself (Apple clang has none; a deterministic mutation driver stood in).
- Other `.npy` readers besides NumPy.

## Not reproduced, and by design

Every reproduced trigger re-ran on the pinned install. The following were judged by design, with their citations:

- the headers NumPy reads but zunpy refuses: Python 2 `L` suffixes, `0x2`, `u''`, comments and the like (§9.2, §9.3);
- archives with directory entries or non-`.npy` members, which abort the whole read (§10);
- `max_size` counting every declared member under `names =` (§10);
- fractional difftimes in their own unit, which are refused (§7.1);
- one byte after the end record, which is refused (§10).
